# Privacy and Data Handling

This project uses fully synthetic data created for educational and portfolio purposes. It does
not use employer data, patient information, protected health information, or confidential
business information.

## How the data was produced

Every record was generated by `src/generate_data.py` using Python with a fixed random seed
(5150). Appointment identifiers, waitlist identifiers, provider identifiers, specialty names,
dates, and statuses are invented. The organization name Frontier Specialty Care Network is
fictional and is not intended to refer to any real entity.

Scheduling is an area where real data is unusually sensitive, so the design goes further than
avoiding names:

- **There is no patient entity at all.** Patients are represented only as `Group A` through
  `Group D`, four arbitrary buckets. There is no patient ID, no date of birth, no sex, no
  address, no travel distance in miles — only a three-band travel category.
- **No provider is a real person.** Providers are `PRV-001` through `PRV-022` with a specialty
  and a slot count, nothing more.
- **No appointment reason, diagnosis, or clinical content exists** anywhere in the schema. Visit
  type is New Patient, Established, or Follow-Up, which carries no clinical meaning.
- **Cancellation reasons are six generic operational categories** chosen to be non-identifying.

The behavioural patterns in the data — longer waits for new patients, lower no-show rates where
a reminder was sent, cancellations clustered close to the appointment, uneven utilization between
peers — were written into the generator by hand because they are common and instructive. They are
illustrative of patterns, not derived from any real system, and no finding in this repository
should be read as a statement about any real clinic.

## What this repository does not contain

- No patient names, identifiers, dates of birth, addresses, contact details, or clinical detail
- No real provider, clinic, or network names
- No employer data, internal documents, screenshots, or configuration
- No credentials, connection strings, or environment files
- No dollar figures, since none could be produced honestly from synthetic data

## Safe-portfolio practices followed

- Synthetic generation only; no anonymization or de-identification of real data, because no real
  data was involved
- Fictional organization, providers, and reference data
- Patient grain deliberately coarsened to a four-value group so the dataset cannot be made
  patient-level even by someone modifying it casually
- Findings described as modeled opportunity subject to validation, never as realized results
- `.gitignore` excludes database files, environment files, and temporary Office lock files

## If you are reusing this work

Do not substitute real scheduling data into these scripts and push the result. Appointment data
is PHI under HIPAA even without a diagnosis attached — dates of service and provider identity are
themselves identifiers. The privacy posture of this repository depends entirely on the data being
synthetic and on there being no patient grain to populate.
